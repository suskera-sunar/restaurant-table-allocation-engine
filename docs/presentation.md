# Presentation outlines

> Two presentations, two different jobs. **Mid-term (20 marks):** prove you're on track — show working software, however small. **Final (internal 30-mark share + external 10 marks):** prove it's done — the demo is the star. Build slides from these outlines; one idea per slide.

## Rules that earn marks (both presentations)

- **The demo is live, in the running app.** Screenshots are the backup plan (keep them in the deck's appendix in case the laptop dies), never the plan.
- **Every member speaks**, and any member can be interrupted with a question — examiners do this deliberately to catch passengers.
- **Rehearse twice, timed.** The first run always takes double the time you think. Cut slides, not speed.
- Slides carry pictures, diagrams, and 5-word phrases — never paragraphs. If you'd read the slide aloud, delete the words and just say them.

## Mid-term presentation (~10 minutes, 8–10 slides)

1. **Title** — project name, team, supervisor.
2. **The problem** — one slide, no technology words. *(From proposal §3.)*
3. **What we're building** — the must-have list, one line each. *(From proposal §5.)*
4. **How it's built** — the system flowchart. Narrate one request's journey. *(From `flowcharts.md`.)*
5. **Data model** — the ER diagram. Point at one relationship and explain it.
6. **LIVE DEMO** — the CRUD core working: create a record as customer, see it as staff, manage it in admin. 3–4 minutes. This slide is just the word "Demo".
7. **The intelligent component** — the formulation (states/goal or rules) and the algorithm chosen, with the one-sentence *why*. If `ai/` already runs standalone, show it — instant credibility.
8. **Schedule** — planned vs actual so far, honestly. What's next before pre-final.
9. **Questions.**

## Final presentation (~12 minutes, 10–12 slides)

1. **Title.**
2. **The problem** — tighter than mid-term; 30 seconds.
3. **What we built** — the must-have list with every box ticked (and any honestly un-ticked).
4. **Architecture** — flowchart, briefly; you'll be asked details in the viva, not here.
5. **LIVE DEMO, part 1** — the full user journey, customer through staff. 3 minutes.
6. **The intelligent component** — the formulation, then *walk one real example by hand* on a slide (this is what proves you understand it).
7. **LIVE DEMO, part 2** — the AI feature inside the app, on the same data you just hand-walked. Matching output = the money moment of the whole presentation.
8. **Testing** — the test table summary and one bug you found and fixed.
9. **Limitations & future work** — honest and short; pre-empts the harshest questions.
10. **What we learned** — one line per member, in their own words. Examiners consistently love this slide.
11. **Questions** — then it flows into the viva; see `viva-prep.md`.
